# Европротокол+

«Европротокол+» — учебное приложение для первичной регистрации дорожно-транспортных происшествий, связывания данных об участниках и автомобилях и контроля оповещений экстренных служб.

## Назначение и аудитория

Приложение сокращает время сбора основных сведений о ДТП и показывает, когда происшествие требует участия экстренных служб. Пользователи: водители — участники ДТП, сотрудники ГИБДД и экстренных служб.

## Предметная область и сущности

- ДТП: место, время, признаки пострадавших и возгорания, состояние обработки;
- участник ДТП: ФИО, телефон, связь с ДТП и автомобилем;
- транспортное средство: государственный номер, марка и модель;
- оповещение: служба, время отправки, состояние доставки.

## Реализованные функции

- классификация происшествия и определение необходимости экстренного вызова;
- просмотр журнала и подробной карточки ДТП;
- просмотр связанных участников и автомобилей;
- фильтрация ДТП по признакам опасности;
- агрегированная статистика по категориям и адресам;
- чтение и запись объектов предметной области в JSON;
- перенос исходных JSON-данных в SQLite;
- получение данных из SQLite посредством SQL в Django-представлениях.

## Архитектура

Проект сохраняет консольную версию ПР2–ПР3 (`main.py`, `models/`, `services.py`, `storage.py`) и дополняет её веб-приложением ПР5–ПР7 (`europrotocol/`, `homepage/`, `accidents/`). Django ORM на этапе ПР7 намеренно не используется: SQL выполняется через стандартный модуль `sqlite3`.

```text
personal_project/
├── accidents/              # Django-приложение журнала ДТП
├── data/                   # исходные JSON и файл SQLite
├── db/                     # подключение, импорт и выполнение SQL
├── europrotocol/           # конфигурация Django-проекта
├── homepage/               # главная страница
├── models/                 # классы консольной версии
├── sql/                    # схема и набор запросов
├── static/                 # собственные CSS и JavaScript
├── templates/              # базовый и общие шаблоны
├── tests/                  # тесты предметной логики и страниц
├── main.py                 # консольный интерфейс
└── manage.py               # управление Django
```

## База данных

Файл `sql/schema.sql` создаёт четыре связанные таблицы:

| Таблица | Основные поля | Ключи и связи |
|---|---|---|
| `accidents` | `location TEXT`, `occurred_at TEXT`, `has_injured INTEGER`, `has_fire INTEGER`, `status TEXT` | `id` — первичный ключ |
| `vehicles` | `plate_number TEXT`, `brand TEXT`, `model TEXT` | `id` — первичный ключ, номер уникален |
| `participants` | `full_name TEXT`, `phone TEXT` | `id` — первичный ключ; `accident_id` и `vehicle_id` — внешние ключи |
| `emergency_messages` | `service_name TEXT`, `sent_at TEXT`, `status TEXT` | `id` — первичный ключ; `accident_id` — внешний ключ |

`db/import_json.py` пересоздаёт содержимое таблиц из четырёх JSON-файлов. `sql/queries.sql` содержит 10 демонстрационных запросов: по два запроса на выборку списков, `WHERE`, `JOIN`, агрегатные функции и `GROUP BY`. Веб-страницы используют именованные строки `sqlite3.Row`, передают результат через контекст и отображают его в шаблонах.

## Запуск

Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m db.import_json
python manage.py check
python manage.py runserver
```

После запуска доступны страницы:

- `/` — главная страница и сводные показатели;
- `/accidents/` — журнал ДТП;
- `/accidents/<id>/` — связанная информация об участниках и оповещениях;
- `/accidents/search/` — фильтрация посредством `WHERE`;
- `/accidents/participants/` — результат объединения трёх таблиц;
- `/accidents/statistics/` — `COUNT` и `GROUP BY`.

Консольная версия запускается командой `python main.py`.
